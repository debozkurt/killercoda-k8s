Module 01b · Workloads

Jobs & CronJobs

Controllers whose goal is finishing, not staying up — a Job drives Pods to completion; a CronJob runs one on a clock.

Desired state = N successful exits, not N running Pods. And Complete ≠ correct.

Objectives

What you'll walk away with

  • Job vs Deployment — N successful exits, not N running Pods
  • restartPolicy — OnFailure vs Never on failure
  • backoffLimit — retrying vs permanently Failed
  • completions / parallelism — fixed-count + sharded; Complete ≠ correct
  • CronJob → Job → Pod — and why a CronJob never fires
Why it matters

Batch failures are quiet

No traffic drop, no page — until the data is stale.

Migration gives up

Hits a bug, retries to backoffLimit, stops. The release never learns.

CronJob suspended

Paused for maintenance, never resumed. Creates nothing; looks fine.

Export reports done

Runs one shard, says Complete, ¾ of the data untouched.

Mental model

Same machinery, opposite goals

Same controller reconciling spec vs status — inverted goals.

Deployment — keep running

Desired: N Pods Running

An exit = failure → replace, forever. No "done".

Job — run to completion

Desired: N Pods exited 0

An exit = progress → at target Complete, stop.

The inversion explains the rules: no restartPolicy: Always · backoffLimit · completions / parallelism.

Sizing the work

completions counts successes; parallelism caps concurrency

completions: N

Pods that must succeed for Complete. Default 1.

parallelism: P

Pods running at once. Independent of completions.

e.g. completions: 4, parallelism: 2 → four units, two at a time.

completionMode: Indexed → each Pod a fixed JOB_COMPLETION_INDEX (0…N-1); a missing index = exactly which shard failed.

The load-bearing insight

Complete is not correct

Complete the instant succeeded reaches completions — even if completions is wrong.1

Wrong size, green status

completions: 1 on 4-shard work → 1/1, Complete, ¾ skipped. Nothing errors.

Right size, real done

completions: 4 → 4/4, every shard processed.

Correctness lives in completions matching the work. The batch form of Running ≠ ready.

A multi-container gotcha

An ordinary sidecar never lets the Job finish

A Pod is done only when every container exits. A forever-sidecar holds it open.

Ordinary sidecar

Log shipper as a normal container. Main exits 0; tail -f runs on.

resultPod Running, Job stuck 0/1

Native sidecar

Init container + restartPolicy: Always. Kubelet stops it when main exits.

resultmain exits → Pod Complete

breakfix-04 — fix = native sidecar, then recreate (Jobs are immutable).

Fixing batch workloads

Jobs are immutable; CronJobs you patch

A Job is one execution — template and completions are locked. Don't patch; delete and recreate.

# CronJob — patch the field in place (breakfix-01) kubectl patch cronjob cdr-rollup -n cdr-storage -p '{"spec":{"suspend":false}}' # Job — immutable; delete + recreate (breakfix-02 / -03) kubectl delete job schema-migrate -n provisioning kubectl apply -f schema-migrate.yaml

Mutable Job fields: parallelism · suspend · activeDeadlineSeconds · ttlSecondsAfterFinished — how it runs, not what it is.

Recap

What to carry forward

  • Desired state = N successful exits. Explains no Always · backoffLimit · completions.
  • OnFailure → same Pod, RESTARTS climb; Never → new Pod each try. Retrying ≠ Failed.
  • Complete ≠ correct — green when succeeded == completions, even if that's wrong.
  • CronJob → Job → Pod. Misbehaving? Find the broken link. First reads: SUSPEND, LAST SCHEDULE, ACTIVE.
  • Jobs immutable (delete+recreate); CronJobs patchable.
Production thinking

Questions to consider

  • A CronJob hasn't fired in three weeks and nothing paged. What signal makes a missed run as loud as a down service — and where does it come from?
  • A migration Job is Failed. It won't re-run on the next reconcile the way a Deployment self-heals. What has to happen for the fixed Job to actually execute?
  • Sizing concurrencyPolicy + activeDeadlineSeconds for a rollup that runs long: what does each protect against — and Forbid (skip) vs Allow (two racing)?
