Kustomize:
bases, overlays, and the render

One base, many environments, no templating language. Kustomize transforms plain YAML with more YAML, and kubectl has it built in.

A failure lands in one stage of the build, apply, and runtime pipeline. The stage decides the first command.

Per-environment copies drift

A folder of full manifests per environment

An engineer copies each Pod spec fix into every file. The day one copy is missing, lab and prod diverge without notice.

One base, one overlay per environment

The base holds what every environment shares. Each overlay states only how its environment departs from the base.

e.g. prodmore replicas, a pinned image
labverbose logging
regionits own node placement

An overlay names the base in resources:

# base/kustomization.yaml namespace: edge resources: - deployment.yaml - service.yaml configMapGenerator: - name: edge-relay-config literals: [LOG_LEVEL=info, MAX_SESSIONS=500]
# overlays/prod/kustomization.yaml resources: - ../../base images: - {name: nginx, newTag: "1.27"} patches: - path: replicas-patch.yaml
  • resources: accepts manifest files and other kustomization directories.
  • A fix to the base reaches every environment on the next build.

One name typo, two ways to target a patch:
opposite failures

Patch file, no target:

The patch names exactly one resource by its own kind and metadata.name. If that resource is missing, Kustomize fails the build.

failed to find unique target for patch

Patch with a target: selector

Kustomize applies the patch to every resource that matches all specified fields. name is an anchored regular expression: relay means ^relay$.

Zero matches is not an error. Kustomize prints nothing and exits 0.

The only evidence of a dropped selector patch is the render. Read the field you meant to change.

Strategic-merge sets fields;
JSON 6902 operates on positions

Strategic-merge

A partial resource. Kustomize merges lists by their merge key, such as a container by its name.

JSON 6902

An operation list (add, replace, remove) against exact paths. It needs a target:, and a reordered list breaks an index path.

Kustomize detects the dialect from what the entry contains. patchesStrategicMerge and patchesJson6902 are deprecated in favor of patches:.

A config change becomes a rollout
through the name-suffix hash

1 New data gives a new hash and a new ConfigMap name.
2 Kustomize writes the new name into every reference.
3 The Deployment's Pod template changes.
4 The Deployment controller starts a rollout, and the new containers read the new values.

Step 2 depends on a name match. A reference that does not name the generator exactly stays bare, and the kubelet fails the container with CreateContainerConfigError.

A container reads envFrom once, at start

Name-suffix hash on

A config edit gives a new ConfigMap name. The Pod template changes, the Deployment rolls, and the new containers hold the new value.

disableNameSuffixHash: true

The name stays fixed. The edit updates the ConfigMap in place, no Pod template changes, and nothing rolls. Every running container keeps the old value.

Teams disable the name-suffix hash to stop old ConfigMaps from accumulating. apply -k --prune -l <selector> removes the leftovers and keeps the rollout.

different reach

Other transformers: namespace, images, and namePrefix/nameSuffix, which also update references.

A Deployment selector is immutable
after creation

$ kubectl diff -k overlays/prod The Deployment "edge-relay" is invalid: spec.selector: Invalid value: ...: field is immutable
  • The selector is how the Deployment finds the ReplicaSets and Pods it owns.
  • On a first create, commonLabels is harmless. Over a running Deployment, the API server rejects the selector change.
  • If the label must be in the selector, the only path is to delete and recreate the Deployment, which is an outage.
  • Fix: labels: with includeSelectors: false, plus includeTemplates: true if the Pods need the label.

apply -k is not a transaction

$ kubectl apply -k overlays/prod configmap/edge-relay-config-... created service/edge-relay configured The Deployment "edge-relay" is invalid: spec.selector: Invalid value: ...: field is immutable
  • apply -k sends each rendered object on its own. When the API server rejects one object, the others still apply.
  • e.g. commonLabels over a running Deployment: the API server rejects the Deployment and accepts the Service, because a Service selector is mutable.
  • The Service selector then carries a label that no running Pod has, so the Service selects no Pods. A rejected lab-to-prod promotion becomes a traffic outage.

A base packages resources;
a component packages a change

Base

Resources every overlay starts from. Its patches change only its own resources.

Component

A kustomization with kind: Component. An overlay includes it through components:. Its patches and generators apply to the resources of the overlay that includes it.

e.g. a regional-affinity pin: prod enables it, lab skips it, one definition serves both.

In the last row the headline status lies: a green CI deploy job, a complete rollout, and Running Pods report on the render you produced, not the render you meant.

Recap

  • Kustomize renders; it never runs. The cluster receives plain objects.
  • The stage decides the first command. A wrong render produces no error, so read the render.
  • A patch file fails loudly; a target: selector can match nothing in silence.
  • The name-suffix hash turns a config change into a rollout through a name match.
  • Transformers that reach a selector collide with immutability.

Production thinking

  • A selector patch that matches nothing ships an environment without its change. Which CI assertions would you add per overlay, and who owns the list of fields each overlay must set?
  • The team disabled the name-suffix hash to stop old ConfigMaps from piling up. What changes on the next edit, and which cleanup would keep the hash on?
  • A render is clean on a laptop and different in CI. What would you pin so that a build is reproducible everywhere?
  • The same patch is copied into five overlays. When does it become a component, and what does an early extraction cost?
